Assumptions Made

Effective Date Generation (effective_date_utc): Implemented as a SQLite STORED generated column:
sql
effective_date_utc TEXT GENERATED ALWAYS AS (
    COALESCE(taken_override_utc, exif_date_utc, created_utc, modified_utc)
) STORED
A STORED generated column calculates values on write and allows creating a direct B-tree index (CREATE INDEX idx_image_effective_date ON image(effective_date_utc)), avoiding query-time COALESCE overhead during filtering and grouping.
Nullable File Timestamps in Image Table: While files on disk typically have created and modified timestamps, created_utc and modified_utc were marked nullable in the schema so that in rare instances where files lack filesystem timestamps (or are inserted without them), all four date candidates can be null, matching Section 7's requirement that the Years view can display an "Unknown" date bucket.
Incremental Versioning Mechanism: To ensure MSBuild triggers assembly recompilation when only time passes between builds, an intermediate version stamp file ($(IntermediateOutputPath)version.stamp) is written before BeforeCompile and added to CustomAdditionalCompileInputs. This causes MSBuild to detect input changes between subsequent runs and update the assembly version and adjacent version.json.
CI Workflow: As permitted in Phase 1 scope ("Skip it if you think it is premature"), GitHub Actions workflow creation was deferred to Phase 11 polish.
Deviations from the Brief
SQLite Dependency Upgrade for Vulnerability Mitigation: When restoring dependencies under .NET 10, NuGet flagged a known upstream vulnerability in SQLitePCLRaw.lib.e_sqlite3 (<= 2.1.11, GHSA-2m69-gcr7-jv3q
). In accordance with warnings-as-errors policy, an explicit reference to SQLitePCLRaw.bundle_e_sqlite3 (version 3.0.3, Apache-2.0) was added to ensure non-vulnerable native SQLite binaries are resolved.
CLI Executable Naming: Set <AssemblyName>iconchest</AssemblyName> on IconChest.Cli so that the compiled binary is named iconchest (or iconchest.exe on Windows), directly matching the test commands specified in the project brief.

4. Assumptions & Decisions
 a) *SVG Dimensions & Units*: Scaled SVG physical units (e.g., in, cm, mm, pt, pc) to CSS pixels using the standard 96 DPI. Dimensionless viewBox coordinates are used as pixel fallback when width/height attributes are omitted.
 b) *Transparency Sniffing*: Tested for raster images (png, gif, webp, ico) up to 2 MB using SkiaSharp alpha channel scanning. SVGs default to Unknown (or null) until rasterized during Phase 3 thumbnailing.
 c) *Move Reconciliation*: Matches candidate files by (hash, size_bytes) across the library move pool where files are missing on disk. Same filename takes precedence; ties are broken by lowest existing record ID.
 d) *Duplicate Recalculation*: Automatically recalculated during scans and whenever images are hidden or unhidden. Hidden images and missing images (is_hidden = 1 or is_missing = 1) do not count toward duplicate pairings.

# Phase 3 - Completion Summary

IconChest Phase 3: Thumbnails — Complete

Phase 3 (Thumbnails) has been implemented and verified. All unit tests pass, the full solution builds cleanly with zero warnings/errors, and the explicit 2,000-image benchmark completes with high throughput.

1. What was built

a) Schema Migration 0003_thumbnails.sql:

Dropped the unpopulated Phase 1 thumbnail_job table.
Created the persistent thumbnail table keyed by (hash, size) with states (pending, running, done, failed, evicted, orphaned), priorities, retries (attempts, next_attempt_utc), dimensions, byte size, access timestamps, and claim timestamps.
Added indexes: idx_thumbnail_claim for prioritized job claiming and idx_thumbnail_evict for LRU cache eviction.
Updated schema version to 3.

b) Settings Additions (AppSettings):

ThumbnailQuality: Integer between 1 and 100 (default 85).
ThumbnailWorkers: Worker count where 0 = Auto (min(4, Environment.ProcessorCount)), or explicit positive integer (default 0).
Validation and cloning tests updated.

c) Skia Thumbnail Renderer (IThumbnailRenderer / SkiaThumbnailRenderer):

High-quality bicubic downscaling using Mitchell filter with premultiplied alpha (preventing edge halo artifacts).
Preserves aspect ratio without upscaling raster images (images smaller than target dimensions keep natural dimensions).
Vector SVG exception: Small SVGs scale up cleanly to fill the target box while preserving aspect ratio.
Automatic EXIF orientation normalization.
Multi-frame selection: largest frame for ICO, first frame for animated GIF/WebP/PNG.
Security guards: 200-megapixel decompression bomb guard, SVG script/external entity protection, and 10-second timeout.
Typed error results: Unreadable, TooLarge, Timeout, Unsupported.

d) Thumbnail Disk Cache (IThumbnailCache / ThumbnailCache):

Fan-out layout: <cache>/<first 2 hex of hash>/<hash>_<size>.webp.
Atomic writes using temporary files (.tmp) and atomic replacement.
Stale .tmp file cleanup on startup.
Total byte calculation and selective deletion.

e) Persistent Thumbnail Queue (IThumbnailQueue / ThumbnailQueue):

Idempotent enqueueing: EnqueueForImages, EnqueueForFolder, EnqueueAll.
3 sizes per distinct hash (64, 128, 256). Duplicates share jobs and missing/unreadable files are skipped.
Never re-enqueues evicted rows automatically.
Prioritized FIFO claim order (priority descending, size ascending: 64 
→
→ 128 
→
→ 256).
Exponential retry backoff on transient errors (30s 
→
→ 2m 
→
→ 10m; marked failed after 3 attempts or on deterministic errors).
Crash recovery (RecoverInterruptedJobs) and manual retry (RetryFailed).

f) Background Worker Engine (ThumbnailWorker):

Concurrency controlled by ThumbnailWorkers setting.
Event-driven wakeup via NotifyWorkAvailable() with delayed-retry polling fallback.
Graceful cancellation (StopAsync) and pause/resume coordination.
Automatic cache eviction check when the queue drains.

g) Thumbnail Provider (IThumbnailProvider / ThumbnailProvider):

GetAsync(imageId, size) returning Ready, Pending, Failed, or NotFound.
Self-healing: Automatically re-enqueues if a disk file is unexpectedly deleted.
ETag generation ("{hash}_{size}_{bytes}").
Periodic batched access-time tracking (flushed every 30 seconds).
LRU cache eviction down to 90% when disk usage exceeds ThumbnailCacheMaxMb.
ThumbnailSizes.PickFor(displayPixels) helper.

h) Orphan Cleanup and Scanner Integration:

CleanupOrphans() wired into LibraryFolderService.RemoveFolder and missing file cleanup.
LibraryScanner enqueues new/changed/moved/restored images upon scan completion and reports ThumbnailsEnqueued in scan results.

iconchest thumbs run [--until-empty]: Runs workers in foreground with live rate/ETA.

IconChest Phase 4: The API — Implementation Complete

Phase 4 of IconChest has been built, tested, and verified according to the Master Project Brief and Phase 4 specifications.

1. Summary of Deliverables

A. HTTP Hosting & Child-Process Contract

Process Contract:
 - Added command-line arguments: --port N (0 = ephemeral port, or default from settings.json), --parent-pid N, and --swagger.
 - Configured stdout readiness line: ICONCHEST_READY http://127.0.0.1:<port>.
 - Built ParentProcessMonitorService: monitors the parent process PID every 2 seconds and triggers graceful shutdown if the parent desktop shell exits.
 - Added POST /api/system/shutdown for programmatic exit.
Static Asset Hosting & SPA Fallback:
 - Configured Kestrel with UseStaticFiles and SPA fallback routing to wwwroot/index.html.
 - index.html is served with Cache-Control: no-cache.
 - Fingerprinted static assets are served with long-term immutable caching (max-age=31536000, immutable).
 - Dotfiles (/.env, /.git, etc.) are explicitly rejected with 404 Not Found.


B. Security & Session Authentication

Loopback Secret Auth:
  - Loops back to ICONCHEST_API_SECRET environment variable or generates a 256-bit cryptographically secure URL-safe base64 secret printed once to stdout at startup.
  - Loopback authentication allows secret login only from loopback IP addresses (127.0.0.1, ::1).
LAN Password Auth:
  - Supports LAN access when api.allowLan = true with a PBKDF2-SHA256 password hash (600,000 iterations, 16-byte cryptographically secure salt).
  - Enforces loopback-only binding if api.allowLan = true but no LAN password hash has been configured.
Session Lifecycle:
  - Uses SessionManager issuing sliding 24-hour sessions with token cookies (iconchest_session, HttpOnly, SameSite=Strict, Path=/).
  - DELETE /api/session terminates the session and expires the cookie.
Rate Limiting & Throttling:
  - Built LoginThrottler: 5 failed attempts per IP within a 1-minute window triggers 429 Too Many Requests with exponential Retry-After headers (60s, 120s, 300s). Successful login immediately resets the counter.
Network & Header Defenses:
  - DNS-Rebinding Protection: SecurityMiddleware validates the Host header against loopback and configured LAN addresses, rejecting foreign hosts with 400 Bad Request.
  - CSRF / Origin Check: Non-GET requests with foreign Origin headers are rejected with 403 Forbidden.
  - Content Security Policy: Global CSP defaults to default-src 'self'.
  - SVG Sandbox CSP: When streaming SVG images via GET /api/images/{id}/file, a strict sandbox CSP (default-src 'none'; style-src 'unsafe-inline'; img-src data:; sandbox) is applied to isolate SVG execution.
  - Secrets Invariant: Session secrets, passwords, cookies, and login request payloads are strictly barred from log files and diagnostic output.

C. OpenAPI Documentation
 - Configured Swagger via Microsoft.AspNetCore.OpenApi and Swashbuckle.AspNetCore.
 - Serves Swagger UI at /swagger on the same origin.
 - Included cookie authentication definition (iconchest_session) in Swagger definition.

Migration 0004_api_indexes.sql:
  Added covering index idx_image_folder_dir on image(is_hidden, is_missing, folder_id, directory_key, directory_path).
  Added covering index idx_image_effective_tree on image(is_hidden, is_missing, effective_date_utc).
  Added expression index idx_image_year_month on image(is_hidden, is_missing, SUBSTR(effective_date_utc, 1, 4), SUBSTR(effective_date_utc, 6, 2)).
  Added reverse lookup index idx_image_tag_reverse on image_tag(tag_id, image_id).
Core Services Implemented:
  TagService: Tag CRUD, hex color validation, case-insensitive uniqueness, image tag unlinking on tag deletion.
